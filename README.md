# pair-wise-yf-57 野外巡护离线调查应用

## 源提示词摘要
巡护员离线记录观察、轨迹点、样本编号、风险等级和现场情况，回到有网络环境后同步给站点负责人。负责人复核重复观察、位置异常、证据缺失和能力范围外事项；多人修改同一记录时保留版本并允许合并，应用需要适配手机屏幕、电量、弱网和后台恢复。

## 技术栈
Taro 3 + React + TypeScript + NutUI + Redux Toolkit + React Hook Form + Zod。

## 离线巡护包闭环（src/patrol/）
- **设备内连续序号 + 稳定巡护标识**：每台设备维护只增不减的包序号 `seq` 和条目序号 `ordinal`（`types.ts`），时钟回拨不影响排序；所有包带 `patrolId`，多台设备把同一次巡护拆成多包也能归并。
- **重传幂等**：`ingest.ts/processPacket` 只在首次处理时写库并把回执固化为 `firstResult`，之后重传原样返回第一次结果，迟到旧包（`seq <= 服务端水位`）只判重、不覆盖任何结论；缺序号按水位登记缺口。
- **业务键去重**：观察键=采集人+设备时间+规范化内容，轨迹键=分钟+5 位坐标，样本键=现场编号（`businessKeys.ts`）。多设备重复上报只保留首次入库那条。
- **时间回拨处理**：轨迹按 `ordinal` 排序，检测到设备时间倒退/位移超速只做异常标记，不影响入库。
- **样本逐段交接**：采集→交接→送检，每段带 `prevHash/hash` 哈希链，写入后不可修改；负责人退回只**追加作废记录**作废受影响样本的后续段，采集段保留，补齐核准后从退回点重新交接（新段接在链尾）。
- **负责人复核**：按能力范围、位置异常（与最近轨迹距离）、证据缺失三项判定；结论按业务键**版本化**保留，旧包顶不掉；退回时列出待补材料。
- **补材料**：以独立补充条目追加（不改原始记录），封包同步后缺失清单自动核销，可从退回点继续。
- **设备换人/旧机升级**：旧版 App 记录标记 `legacy`，仅保留采集人与时间；设备切换后旧记录仍在，升级 App 后可查看并继续交接。
- **逐条容错**：单条处理被 try/catch 隔离，失败不影响同包其他条目；页面逐条展示接收/待复核/重复/失败、失败原因和待补材料。

## 页面（五个页签）
1. 现场：记录观察/轨迹/样本（证据、能力、标签勾选）、草稿封包、设备时钟偏移模拟。
2. 同步：待同步包一键按序号入库；已处理包展示每包逐条结果、缺包提示，重传验证幂等。
3. 复核：观察/样本的核准与退回、补材料、样本交接/送检按钮（退回中禁用）。
4. 台账：样本哈希链（含作废段与原因）、轨迹异常、观察业务键、补材料与复核版本、审计日志。
5. 设备：多设备换人、旧机升级、演示指引、重置演示数据。

## 验证
```bash
npm run build                     # 类型检查 + 生产构建
./node_modules/.bin/esbuild verify.cjs --bundle --platform=node --format=cjs --outfile=/tmp/v.cjs && node /tmp/v.cjs
```
`verify.cjs` 覆盖：多设备去重、时间回拨、缺包检测、逐条失败隔离、重传结果不变、退回只作废后续交接、补齐后重新交接上链、同阶段交接拒绝、旧包不顶复核结论。
